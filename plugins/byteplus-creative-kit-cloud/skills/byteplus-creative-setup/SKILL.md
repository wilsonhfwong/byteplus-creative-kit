This is a skills-only cloud plugin. It has no MCP server connection, desktop launcher, or browser setup form. Run its bundled commands with the cloud executor's shell/code tools. A chat without a cloud executor cannot run it; explain that requirement without directing the user to install the desktop app.

Resolve the plugin root from this skill's location: this file is `skills/byteplus-creative-setup/SKILL.md`; the runner is `../../scripts/run.py` relative to its containing directory. Use the resolved absolute runner path in every command. Do not assume `${PLUGIN_ROOT}` expands inside skill text.

If the host has exposed this skill but has not copied its runner files into the workspace, **restore the runtime from this skill's bundled resources first**, without GitHub or external HTTP requests:

1. Read `references/runtime-manifest.json` using the skill-resource reader for this setup skill. It lists ordered `parts` resource names and the SHA-256 of a ZIP encoded across them.
2. Read each part through the same skill-resource reader, preserving the exact base64 contents and order. Resolve each relative path against this setup skill's directory, not the repository root. Decode the concatenated base64 with Python's standard library and verify the manifest's `sha256` before extracting.
3. Extract into a new writable workspace directory, rejecting archive paths containing traversal, absolute paths, or symbolic links. The decoded archive contains runner code and locked dependency declarations, never credentials. Use the restored directory's `scripts/run.py`.
4. If bundled resources are unavailable, a user-uploaded plugin ZIP is a second offline source: extract that attachment rather than fetching GitHub over a broken proxy. GitHub retrieval from branch `codex/byteplus-creative-kit-cloud`, directory `plugins/byteplus-creative-kit-cloud`, is a last fallback when networking works.

A workspace proxy connection failure is separate from a missing runner or denied provider domain. Preserve proxy and CA configuration. If the shell reports `Operation not permitted`, `Permission denied`, or a proxy connection failure before reaching a destination, check whether the command was run without the execution tool's network permission. Re-run an unbilled dependency/preflight command using the supported network-enabled execution option (for example, exec_command sandbox_permissions="with_additional_permissions" and additional_permissions.network.enabled=true when offered). This preserves the enforced destination policy and proxy. If that option requires approval, request the tool permission. A provider destination-policy denial instead requires updating allowed domains. If the proxy remains unreachable with network-enabled execution, restart/recreate the cloud environment using its published configuration and recheck. Do not unset the proxy or repeat a billed submission to diagnose networking.

Run `python3 <runner> --check` to inspect configuration flags without contacting BytePlus. `--check` uses Python standard-library code only and works without uv, installed dependencies, or network access. Generation commands use uv to install the frozen Python 3.12 environment into a writable workspace directory, then execute one command and exit. If uv is absent, install it using the cloud environment's supported package-manager flow into a writable workspace; do not ask the user to install desktop software. Missing Python or dependency network access is a cloud environment requirement.

Credentials belong in cloud environment secret settings, never chat, source, or command arguments. ARK_API_KEY enables generation. ARK_AK and ARK_SK enable asset-library access. Uploads additionally need SEEDANCE_TOS_BUCKET; defaults are ap-southeast-1 and tos-ap-southeast-1.bytepluses.com. Optional BYTEPLUS_TOS_AK/BYTEPLUS_TOS_SK override upload credentials. Optional BYTEPLUS_SEED_MODEL enables the text command. Report missing variable names only. Do not read, print or collect secret values. Each command reads the current environment; no daemon restart is needed.

Preserve proxy and CA settings and TLS verification. The configured API, asset, bucket and returned media hosts must be allowed by the environment's network policy. Use supported environment configuration for denied destinations. Do not bypass the proxy. Configuration flags do not prove provider access; do not submit paid generation to validate setup.

Outputs default to /workspace/output/byteplus-creative-kit and operation records to /workspace/.byteplus-creative-kit. Override BYTEPLUS_CREATIVE_OUTPUT_DIR and BYTEPLUS_CREATIVE_DATA_DIR when the environment uses different writable or user-downloadable directories. Use persistent storage for operation records where available; return downloadable links to saved results and preserve task/operation IDs. Ephemeral environments do not retain these files after deletion.
